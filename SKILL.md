# Дерево задачи, два конца, всё параллельно

## Заставка — осьминог трясёт деревья
При вызове этого скилла — первым делом в ответе вывести рисунок (один раз на задачу, блоком кода). Падающие листики — задачи, которые снимают агенты.
```
  .  '  *                       *  '  .
   _____          _____          _____
  / * * \        /     \        / * * \
 /* * * *\      | o   o |      /* * * *\
 \_______/      |  \_/  |      \_______/
    | |          \_____/          | |
    | |~~~~~~~~~~/|||||\~~~~~~~~~~| |
 '  | |  .      ~ ~ ~ ~ ~      .  | |  '
  ' | | .                       . | | '
-----------------------------------------
```
Под рисунком — одна строка загрузки: `щупалец занято: N из 8 — <агент: лист>, …` (N — агенты, что работают сейчас).

## Статус деревом
Каждый статус по многошаговой задаче — деревом с отметками, не сплошным текстом:
```
v2.0
├─ ✔ A  форма входа
├─ ⏳ B  экспорт не зависает (агент, ~10 мин)
├─ ✘ C  синхронизация — ревизор: дефект, чинит агент
└─ ·  выпуск — ждёт A–C и проверок
```
✔ готово и проверено мной · ⏳ идёт (кто, сколько осталось) · ✘ сломано/вернули · · ждёт (от чего). Под деревом — 1–2 строки: что нужно от пользователя. Отметку ✔ ставлю только после своей проверки (git, тест, снимок), не по отчёту агента.

Дерево можно вести и на странице: `python -I ~/.claude/skills/octopus/doska.py --help` — доска листьев в `doska/derevo.json` и локальная страница `doska/doska.html`, обновляется сама.

Перед раздачей листов агентам — проверка пересечений файлов: `python ~/.claude/skills/octopus/peresechenie.py <задание1.txt> <задание2.txt> …` (файлы, названные в двух заданиях, — стоп: один файл — один агент). После работы агента — `peresechenie.py sverka <задание> --repo <репо> --ot <база>`: обещал / сделал.

## Карта кода — осьминог × Graphify
Есть `graphify-out/` в репо ([Graphify](https://docs.graphify.com), карта кода) — карта работает на обоих концах дерева:
- **Раздача:** к проверке выше добавить `--graphify <репо>`. Один лист прямо вызывает или импортирует файл другого → СТОП-СВЯЗЬ (один агент или по очереди); через один файл — «сказать обоим»; документ ссылается на код — «сверить текст»; тесты, которые задевает каждый лист, — приёмщику.
- **Нижний конец:** `peresechenie.py zadeto <файл> … --repo <репо>` — кого задевает правка: напрямую, через одного, тесты, документы (2–3 с). Это листья проверки; вывод — в задание строителю («что не сломать») и приёмщику («какие тесты гонять»), вместо чтения репо агентом. `graphify affected` для этого не звать: 33 с на файл и не видит вызов функции без импорта файла.
- «карта старше кода» — `graphify update .` в папке репо (без ИИ; большой репо — минуты) или флаг `--obnovit`. «карта: НЕ ЗНАЮ» — карты нет или формат чужой: проверка не сделана, это не «чисто».
- Карта видит вызовы и импорты, но не общие ключи JSON, поля данных и маршруты-строки — а проекты ломаются молча именно так. Для них grep по точному имени; «связей нет» по карте — не гарантия.

Папки агентов (порядок всегда) — `python -I ~/.claude/skills/octopus/papki.py novaya --repo <репо> --put <папка> --vetka <ветка> [--ot master]`. После КАЖДОГО выпуска — `papki.py ubrat --repo <репо>`: показывает, что убрать; затем с `--da` убирает только слитые, чистые и не тронутые 12 ч (без --force, ветки — только слитые).

## Суть
Любая задача — дерево процессов. Идём по дереву и снимаем листья; всё, что не зависит друг от друга, делается ОДНОВРЕМЕННО; каждая ветка ведётся с двух концов навстречу — от начала (причина, данные, требования) и от конца (как результат попадёт к человеку: выкладка, текст, проверка). Качество не режем: проверки — тоже листья, идут рядом с кодом, а не после.

## Первая минута
1. **Корень** — цель словами пользователя («форма сохраняет все поля», «отчёт у заказчика»).
2. **Ветки** — процессы: факты/причина, работа (код, текст, данные), проверка, доставка (выкладка, файл, ссылка), люди (что им нажать/прочитать).
3. **Листья** — действия на 1–10 минут. У каждого отметить, от чего он ждёт.
Дерево — в голове или 5–10 строк в scratchpad, пользователю не показывать без просьбы.

## Ход
1. Все листья без зависимостей — одним ходом: несколько вызовов инструментов в одном сообщении, агенты в фоне. Агентов — по числу независимых веток в РАЗНЫХ файлах; на один файл — один агент, дополнения ему сообщением.
2. Конец Б стартует в ту же минуту, что А: заготовка выкладки, текста, проверок — пока делается работа.
3. Лист готов — снять и сразу запустить то, что от него ждало. Ждать уведомления, не опрашивать.
4. Проверяющий (ревизор, тесты) читает работу на ходу; его «нельзя» — новый лист тому же исполнителю, остальные ветки не стоят.
5. Встреча концов — короткий финал: тесты/вердикт → доставка → «готово» со своей проверкой.

## Схема (рисунки — `skhema-*.png` в папке скилла)
Одно и то же на каждом уровне: дерево → ветка → лист → сегмент.
1. **Каждый лист — пара.** Строитель идёт от причины (правка), приёмщик — от результата: СНАЧАЛА пишет, что должно быть верно в конце (красные приёмочные тесты, сценарий, текст человеку), потом проверяет сданное. Встреча посередине = его проверки зелёные. Приёмщик стартует в ту же минуту, что строитель, а не после.
1а. **Красный прогон — доказательство, а не слова** (идея fusion-harness): вывод падающего теста (2–3 строки FAIL) сохраняется в записку передачи ДО правки кода; в отчёте агента — путь к нему. Приёмка: красный вывод есть и падает именно тот тест → только тогда лист может стать ✔. Нет красного — тест ничего не доказывает.
2. **Лист дольше ~15 минут режется на сегменты**, у каждого сегмента своя пара. Три вещи в одном задании («проверка ввода + миграция + кнопка») — это три сегмента, три пары одновременно.
3. **Готовый сегмент принимается сразу** — ревизор и живой запуск идут по сегментам и промежуточной склейке, а не по всей сборке в конце.
4. **Критик на каждой работе агента** — всё, что уходит в общую ветку (main/master), на GitHub или в прод, до слияния проверяет независимый агент-критик: ему — задание, `база..ветка`, команда тестов; отчёт автора не давать. ВЕРНУТЬ — лист тому же строителю сообщением. Мелочь, которую правлю сам без агента, — проверяю сам.
Без этого тесты пишутся после кода, а ревизор и песочница идут после склейки — три лишних круга «нашёл → правка → снова проверка».

## Как торрент — чем больше пиров, тем быстрее
| Торрент | Здесь |
|---|---|
| Файл режется на куски | Работа режется на листья — маленькие, независимые, каждый в своих файлах |
| Пиры качают разные куски | Агенты берут разные листья одновременно; больше листьев — больше агентов |
| Трекер раздаёт куски | Я: раздаю листья, сливаю готовое, ничего не пишу сам там, где может агент |
| Хеш-проверка каждого куска | Тест на каждый лист — сразу, до сборки |
| Сначала редкие куски | Сначала самый длинный путь (причина, ядро кода) — от него ждут остальные |
| Пир докачал — раздаёт дальше | Агент сдал лист — следующий лист ЕМУ сообщением (контекст есть, дешевле нового) |
| Сборка файла | Ветка сборки, слияние после каждого листа, полный прогон тестов в фоне |

Предел скорости — самый большой неделимый лист и один файл, который правят все: его режь первым (вынести функцию, отдельный файл), иначе пиры ждут друг друга. Число агентов — по числу независимых листьев, а не «≤2»; в спокойное время — экономнее: каждый агент стоит токенов.

## Два конца — везде, где применимо
| Задача | Конец от начала | Конец от результата (готовится сразу) |
|---|---|---|
| Код/правило | правка | сценарии и законы-тесты ДО кода (краснеют), ревизор на ходу, скрипт выпуска, «Что нового» |
| Жалоба пользователя | разбор жалобы | наблюдатель журнала с первой минуты — узнать раньше, чем напишут снова |
| Сервер/прод | разбор причины | скрипт применения с автооткатом и проверкой — готов до «да» пользователя |
| Исследование | поиск | вопрос «что сделаю с ответом» и место, куда ляжет результат |
Где второй конец осознанно ждёт (инструкция людям — только по снимкам той сборки, что уйдёт), — сказать прямо.

| Мысль | На деле |

| «Подожду, пока все закончат» | Снял лист — запускай зависимое |
| «Проверю в конце» | Проверка — ветка дерева, идёт рядом |

| «Файлы разные — значит листья независимы» | `--graphify`: вызов или импорт между ними — СТОП-СВЯЗЬ |
